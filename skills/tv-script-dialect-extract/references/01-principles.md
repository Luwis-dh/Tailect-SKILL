# 原理与调参

## 1. 为什么用「演播室镜头」当锚点

这类栏目在剪辑上有一条硬约束：**主持人的口播是在演播室一次性录的，新闻片和广告是后期插进去的**。所以：

- 演播室里出现的，一定是主持人；
- 新闻片里出现的同期声（采访路人、商户、民警），一定不是主持人；
- 广告是整段贴片，连画面都是另一套。

于是"找主持人"退化成"找演播室"——一个纯视觉问题，比声纹聚类稳得多，也不受方言影响。

### 检测方法

演播室背景（屏风、背景板、栏目 logo 板）是**全片唯一静止**的画面。取一帧参考，逐帧算差异：

```
差异 = |当前帧 - 参考帧| 在「左右两侧竖条」上的平均像素差
```

- **只取左右侧边**（各 16% 宽）：中间是人物会动，底部是字幕条会变，顶部是台标。
- 阈值 25 左右（0~255 像素值）。漏检调大，误检调小。
- 结果按秒合并，允许 5 秒内的抖动断开（人物大幅移动会闪断）。

### 参数怎么调

先跑 `--ref-time 30`，看输出块数：

| 现象 | 原因 | 处理 |
|---|---|---|
| 0 个块 | 参考帧不是演播室 | 换 `--ref-time`，或直接看 `work/fps1/p_000NN.jpg` 挑 |
| 块数远多于台本段数 | 阈值太松，把别的静态画面算进来了 | 调小 `--threshold`（20/15） |
| 块很碎（2~3 秒一堆） | 主持人动作大，帧差抖 | 调大 `--max-gap`，或把 `--min-run` 提到 4 |
| 某些口播没检出 | 该机位角度不同 | 检查那一帧，必要时用第二个参考帧做并集 |

## 2. 台本 → 段落

串词 docx 里混着四类东西，必须分开：

| 类型 | 例子 | 处理 |
|---|---|---|
| 正文 | `（口播）观众朋友晚上好…` | **保留**，去掉 `（口播）` 前缀 |
| 片名 | `《越城区环城西路352号：…（上）》` | 丢弃 |
| 署名 | `记者 朱琴丽 陈立云` | 丢弃 |
| 广告位 | `广告1:88888888…` | 丢弃 |

判定顺序很重要：先判广告（全是数字/8），再判署名（`^记者`），再判片名（含《》且带"记者"或很短），剩下的才是正文。

> **坑**：`（口播）`标注只覆盖了一部分段落。有的台本只标了 6 段，实际 10 段都是口播。**永远按画面配对，不要按标注筛**。

## 3. 配对

按顺序一一对应（第 k 段台本 ↔ 第 k 个镜头块）。前提是数量相等。

数量不等时的处理：

- **台本多**：多半是某段被剪了（成片时长限制）。多出来的段落列出来人工确认，不要插到中间。
- **镜头块多**：可能有多机位切换、或片头片尾的静态画面被误检。看 `studio_runs.json` 的时长，通常误检的块很短或位置很怪。

## 4. 边界精修：为什么是「拼音 + 局部对齐」

镜头块边界只有 ±1 秒精度，而口播的音频可能比画面早/晚零点几秒。直接用块边界会吃字或带进邻段。

### 对齐代价

把台本和 ASR 都拆成字，用**声母/韵母**算相似度，而不是字面：

| 情况 | 代价 |
|---|---|
| 同一个字 | 0 |
| 声母韵母都同（同音字） | 0.12 |
| 韵母同 | 0.30 |
| 声母同 | 0.50 |
| 无关 | 1.60 |
| 跳过台本字 | 1.00 |
| 跳过 ASR 字 | 0.35 |

**关键点**：`
无关 = 1.60 > 跳过台本 + 跳过 ASR = 1.35`。如果无关字代价低于这个和，DP 会拿广告里的字去硬配台本字，结果就是整段对齐散架（这个坑踩过：初版把无关字设成 1.0，对齐率 99% 但每条都碎成 20 段）。

**为什么 ASR 侧跳字便宜**：广告、采访、新闻片同期声在 ASR 里是真实存在的一长串字，但台本里没有对应内容。让它们"便宜地跳过"，DP 才不会去强行匹配。

### 局部对齐

窗口（镜头块 ±10 秒）里往往混着上一段新闻片的尾音。所以用 Smith-Waterman 找**得分最高的连续子段**，而不是全局对齐。找到的那一段才是台本真正被念到的位置。

### 边界补偿

局部对齐会把"噪声大的头尾"切掉（比如开头一句 ASR 全错）。为了不丢字，按语速把未对齐的字补回来：

```
start -= min(未对齐头字数 / 4.2, 2.5) 秒
end   += min(未对齐尾字数 / 4.2, 2.5) 秒
```

顺序上：**宁可多 0.3 秒音频，不可少一个字**。多音频只是浪费，少字会让"文本-音频"对不上，训练时是硬伤。

## 5. 切分

### 为什么必须切

ASR 训练单条理想 3~10 秒。20 秒以上会带来：batch padding 浪费、标点/对齐误差沿长句累积、出错时无法定位到具体句子。业内做法（含本项目 skill 规范）是 **>20 秒视为超时文件，必须切**。

### 怎么切

1. 用第 4 步的字级时间，拿到每个字的绝对时间；
2. 按台本标点断句（`，。！？；：`）；
3. 贪心合并到 4~10 秒，**优先在 `。！？` 处断开**；
4. 边界吸附到 ±0.3 秒内的**能量谷底**（10ms 帧），避免切在一个字的中间；
5. 合并后仍 < 2.5 秒的短块并入前一块（除非会让前一块超 10 秒）。

### 退化保护

如果某段的字级对齐退化（典型：被广告/新闻片同期声污染，`对齐率 < 35%` 或字时间跨度远小于音频跨度），**整段保留不切**，并打 `quality_flags: ["check"]`。

强行切会产生多条时间重叠、文本对不上的废数据——比不切更糟。

## 6. 质检分

```
质检分 = 台本 与 该时间段 ASR 文本 的 字二元组 Jaccard
```

- 只用来**排序找人复核**，不代表数据质量。
- 方言越重分越低，0.1~0.4 属正常。
- 真正的红线是**语速**：偏离 3.4~4.8 字/秒，说明边界或配对错了。
